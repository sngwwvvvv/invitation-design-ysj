# 행사장 기준 모바일 주차 안내 페이지 구현 계획

## 목표

초대장의 주차 버튼이 사용자 현재 위치가 아닌 행사장 기준의 주차 안내 화면을 열도록 변경한다. 안내 화면은 행사장 좌표와 확인된 인근 주차장 목록을 제공하고, 각 항목은 네이버 지도에서 최신 정보를 확인할 수 있도록 연결한다.

## 작업 순서

### 1. 정적 검증 테스트를 먼저 추가

- `scripts/validate-parking-page.mjs`를 추가한다.
- `parking.html`과 `parking.css`가 없을 때 실패하도록 RED 상태를 확인한다.
- 주소, 좌표, 경고 문구, 주차장 9개, 네이버 검색 URL, `target`/`noopener`, 반응형·포커스 CSS를 검증한다.
- 기존 `validate-invitation-local.mjs`는 주차 버튼이 내부 `parking.html`을 새 탭으로 여는지 검증하도록 갱신한다.

### 2. 모바일 안내 페이지 구현

- `parking.html`에 한국어 문서 구조, 안내 문구, 행사장 좌표, 지도 이미지, 행사장 지도 링크, 주차장 목록을 작성한다.
- 각 주차장명은 URL 인코딩된 네이버 지도 검색 링크로 연결하고 새 탭·`noopener`를 적용한다.
- `parking.css`에 모바일 우선 카드 레이아웃, 기존 색상과 조화되는 버튼, 최소 44px 터치 영역, 키보드 포커스, 360px 반응형 규칙을 추가한다.
- `index.html`의 기존 주차 링크를 `parking.html`로 변경한다.

### 3. 브라우저 검증 추가

- 로컬 정적 서버에서 Playwright 모바일 뷰포트로 `parking.html`을 연다.
- 제목, 경고 문구, 주소, 좌표, 주차장 목록, 첫 번째 네이버 링크를 확인한다.
- 360px 폭에서 가로 오버플로가 없는지 확인한다.
- 기존 초대장 검증 스크립트와 신규 검증 스크립트를 함께 실행한다.

### 4. 통합

- 변경 사항을 기능 커밋으로 만든다.
- 검증 결과를 확인한 뒤 `main`에 fast-forward 병합하고 push한다.
- 기존 Cloudflare 터널은 유지하고, 포트 4173의 로컬 서버만 최신 `main`을 제공하도록 재시작한다.
- 공개 URL에서 `/parking.html`과 정적 자산을 다시 확인한다.

## 위험 및 대응

- 주차 정보는 정적 스냅샷이므로 페이지에 요금·운영시간을 표시하지 않고 네이버에서 최신 확인하도록 안내한다.
- 네이버 지도 모바일 앱의 검색 중심 좌표 무시 문제를 피하기 위해 개별 장소 검색 링크를 사용한다.
- 외부 링크와 내부 페이지 링크를 구분해 기존 링크 검증이 깨지지 않도록 한다.
