# 개업식 초청장 디자인 명세

## 1. 목표

호연회계법인 윤성중 부대표의 개업식 초청장을 단일 HTML 페이지로 제작한다. 페이지는 격식 있고 전문적인 기업형 인상을 주며, 고령 사용자를 포함한 초대 손님이 행사 일시, 장소, 주요 경력과 이동 방법을 쉽게 확인할 수 있어야 한다.

## 2. 범위

### 포함

- 모든 화면에서 동일하게 사용하는 모바일 기준 단일 열 레이아웃
- 제공된 법인 로고와 인물 사진
- 개업 안내 문구, 행사 핵심 정보, 인물 사진과 주요 경력
- API 발급 전 지도 placeholder와 추후 네이버 Web Dynamic Map을 연결할 구조
- 네이버 지도 앱 길찾기 버튼
- 주차 안내 placeholder
- 후원계좌 placeholder와 추후 모달·복사 동작을 연결할 수 있는 구조

### 제외

- 다중 페이지와 서버 애플리케이션
- 네이버 지도 앱 버튼 이외의 외부 이동
- 전화, 이메일, SNS, 홈페이지 링크 및 연락처 표시
- 접힌 약력, 탭, 캐러셀, 자동 재생, 스크롤 애니메이션
- 프런트엔드 프레임워크와 불필요한 외부 라이브러리
- 미정인 소감문, 행사 일시, 주차 안내, 계좌 정보의 임의 작성

## 3. 콘텐츠 원칙

- `initial_ideas.md`에 제공된 이름, 주소와 주요 경력을 사용한다.
- 원문에 오탈자 가능성이 있는 경력 문구는 구현 전에 사용자 확인 없이 임의 수정하지 않는다.
- 소감문, 날짜, 시간, 주차와 계좌는 의미를 알 수 있는 placeholder로 표시한다.
- 행사 주소는 `서울특별시 강남구 테헤란로81길 14, 8층 (카이마빌딩)`으로 표시한다.
- 전화번호, 휴대전화와 이메일은 페이지에 표시하지 않는다.

## 4. 페이지 정보 구조

페이지의 읽기 순서는 다음과 같다.

1. 로고·헤더 문구·행사 핵심 정보를 묶은 상단 영역
2. 상단 영역과 가깝게 이어지는 초청 소감문
3. 경력사항 소개: 왼쪽 인물 사진과 오른쪽 이름·주요 경력
4. 지도·주소·길찾기·주차 안내를 묶은 오시는 길
5. 축하 및 후원계좌 안내

### 4.1 헤더 및 초청 영역

- 최상단에 `/img/hoyeon_logo_vertical.png`를 원본 비율로 표시한다.
- 메인 문구는 `호연회계법인에서의 새로운 출발을 알려드립니다`를 사용한다.
- 로고 → 메인 문구 → 날짜·시간 및 장소 순으로 하나의 상단 섹션에 배치한다.
- 초청 소감문 placeholder는 별도 섹션에 두되, 상단 섹션과 크게 분리돼 보이지 않도록 두 섹션 사이 간격과 맞닿는 패딩을 줄인다.
- 형식은 광고형 히어로가 아니라 공식 안내문 표지에 가깝게 구성한다.

### 4.2 초청 소감문

- 소감문은 임의 내용을 작성하지 않고 placeholder로 표시한다.
- 상단 카드와 같은 배경·테두리 체계를 사용해 시각적으로 연속된 영역처럼 보이게 한다.

### 4.3 경력사항 소개

- 이름: 윤성중 부대표
- 인물 사진: `/img/portrait_ysj.png`
- 전화번호, 휴대전화와 이메일은 표시하지 않는다.
- `국립세무대학 내국세학과 졸업`, `고려대학교 법무대학원 조세법학과 졸업`, `한국세무사`는 표시하지 않는다.
- `initial_ideas.md`의 주요 경력 10개 항목은 모두 처음부터 펼쳐 표시한다.
- 섹션 제목은 `대표자 약력` 대신 `경력사항 소개`를 사용한다.
- `경력사항 소개` 제목 아래를 왼쪽 사진과 오른쪽 텍스트의 2열로 구성한다.
- 왼쪽에는 인물 사진만, 오른쪽에는 `윤성중 부대표`, `[ 주요 경력 ]`, 주요 경력 목록만 둔다.
- 확정한 B안처럼 사진 원본 전체를 자르거나 왜곡하지 않고 표시하며, 사진 열의 아래쪽에 정렬한다.
- 실제 사진 하단과 마지막 주요 경력 문구의 하단을 일치시킨다.
- 좁은 화면에서도 주요 경력은 16px 이상을 유지하고, 행간과 열 간격을 과도하게 줄이지 않는다.

### 4.4 찾아오는 길

- API 키 발급 전에는 캡처 이미지나 iframe 없이 고정 높이의 중립적인 지도 placeholder를 섹션의 첫 콘텐츠로 표시하고, `[네이버 지도 API 연결 영역]` 문구만 중앙에 둔다.
- 운영 환경에서는 placeholder의 같은 DOM 영역에 네이버 Web Dynamic Map JavaScript API 지도를 표시한다.
- 지도는 목적지 중심 좌표, 적절한 줌, 단일 마커가 보이는 순수 지도 상태로 시작하고 검색 결과 패널을 표시하지 않는다.
- 지도 아래에 `서울특별시 강남구 테헤란로81길 14, 8층`을 표시한다.
- 주소 아래에 `네이버 지도 앱에서 길찾기` 버튼을 크게 배치한다.
- 버튼 아래에 주차 안내 placeholder를 같은 오시는 길 카드 안에 표시한다.
- 해당 버튼은 전체 페이지에서 유일하게 외부로 이동하는 요소다.
- iframe은 사용하지 않는다.
- 지도 로딩 실패 시 주소와 앱 버튼을 포함한 fallback을 표시한다.

### 4.5 축하 및 후원계좌 안내

- 확정 전 축하 문구와 계좌 정보는 placeholder로 표시한다.
- `마음 전하실 곳` 버튼은 페이지 안에서 모달을 실제로 열고, 미정 상태에서는 placeholder를 표시한다.
- 계좌 정보가 확정되면 같은 모달에 복사 버튼을 제공한다.
- 복사되는 문자열은 계좌번호에서 하이픈을 제거한 숫자만 포함한다.
- 복사 실패 시 원문을 선택할 수 있도록 화면에서 계좌번호를 숨기지 않는다.

## 5. 시각 시스템

### 5.1 방향

- 공식 안내문형, 격식 있고 전문적인 분위기
- 명확한 제목 계층, 얇은 구분선, 넉넉한 여백
- 장식보다 정보 가독성과 신뢰감 우선
- 강한 그림자, 그라데이션, 과도한 둥근 카드와 애니메이션 제외

### 5.2 팔레트

최대 5색만 사용한다.

| 역할 | 색상 |
| --- | --- |
| 본문 카드 배경: 네이비 | `#142755` |
| 페이지 배경: 서브 그레이 | `#A9AABC` |
| 브랜드 그린 | `#35B84A` |
| 보조 정보·경계선: 웜 아이보리 | `#F6F4EF` |
| 제목·버튼·구분선: 화이트 | `#FFFFFF` |

### 5.3 타이포그래피

- 시스템 산세리프 스택을 사용하고 외부 웹폰트를 요청하지 않는다.
- 본문 최소 16px, 줄 높이 약 1.7.
- 주소와 지도 버튼은 18px 이상.
- 메인 제목은 모바일 34~42px, PC 48~60px 범위.
- 작은 회색 글자에 핵심 정보를 배치하지 않는다.

### 5.4 이미지

- 로고와 인물 사진의 원본 비율을 유지한다.
- 인물 사진은 얼굴과 상반신이 자연스럽게 보이도록 배치한다.
- 별도의 장식용 스톡 이미지나 아이콘 묶음을 추가하지 않는다.

## 6. 단일 화면 동작

- 미디어 쿼리를 사용하지 않는다.
- 모든 화면에서 최대 약 640px의 모바일 단일 열 페이지를 사용하되, 경력사항 카드 내부만 승인된 2열 구조를 사용한다.
- PC에서는 동일한 폭의 콘텐츠를 화면 중앙에 배치한다.
- 경력사항은 왼쪽 사진 / 오른쪽 이름·주요 경력의 2열을 유지한다.
- 모든 주요 경력은 화면 크기와 관계없이 펼쳐진 상태를 유지한다.
- JavaScript로 화면 크기를 감지하거나 레이아웃을 재계산하지 않는다.

## 7. 상호작용과 접근성

- 유일한 외부 이동은 네이버 지도 앱 길찾기 버튼이다.
- 계좌 모달은 페이지 내부 상태만 변경하며 외부 이동을 만들지 않는다.
- 모달은 버튼, Escape 키, 배경 클릭으로 닫을 수 있다.
- 키보드 포커스 표시와 의미론적 제목 구조를 제공한다.
- 버튼 터치 영역은 최소 44px 이상이다.
- 지도 사용이 어려운 경우에도 주소를 읽고 복사할 수 있다.

## 8. 기술 구조

- 결과물은 하나의 HTML 진입점과 로컬 이미지로 구성한다.
- 스타일은 페이지 내부 또는 별도 정적 CSS 한 파일로 제한할 수 있다.
- JavaScript는 지도 연동, 계좌 모달과 클립보드 복사에 필요한 최소 코드만 사용한다.
- 서버 렌더링, 데이터 요청, 라우터, 상태 관리 라이브러리를 사용하지 않는다.
- 지도 API를 사용할 경우 필요한 키와 정확한 장소 좌표 또는 장소 식별자는 구현 전에 별도로 주입 가능하게 둔다.

## 9. 실패 처리

- 지도 임베드가 로드되지 않으면 주소와 앱 길찾기 버튼을 포함한 안내를 같은 영역에 표시한다.
- 클립보드 API가 실패하면 계좌번호 원문과 수동 복사 안내를 표시한다.
- 이미지가 로드되지 않더라도 로고와 인물의 의미를 전달하는 대체 텍스트를 제공한다.

## 10. 검증 기준

- PC와 모바일에서 동일한 단일 열 콘텐츠 순서와 최대 폭이 유지된다.
- 긴 주요 경력이 잘리거나 접히지 않는다.
- 본문, 주소와 버튼의 크기 및 대비가 고령 사용자에게 충분하다.
- 로고와 인물 사진이 왜곡되지 않는다.
- API 연결 시 지도는 검색 패널 없이 목적지 중심·줌·마커 상태로 시작하고 fallback도 같은 핵심 정보를 제공한다.
- 외부 이동 요소를 검사했을 때 네이버 지도 앱 버튼 하나만 존재한다.
- 전화번호, 휴대전화와 이메일이 화면에 표시되지 않는다.
- `마음 전하실 곳` 모달의 열기·닫기와 복사 실패 처리가 키보드 및 포인터 입력에서 동작한다.
- 프레임워크나 불필요한 동적 레이아웃 로직이 포함되지 않는다.

## 11. 구현 전 필요한 값

아래 값은 디자인 변경 없이 나중에 교체할 수 있는 placeholder다.

- 개업식 날짜
- 개업식 시간
- 초청 소감문
- 주차 안내
- 축하 문구
- 은행명, 계좌번호, 예금주
- 네이버 Maps Application의 Web Dynamic Map Client ID(`ncpKeyId`)
- 운영 서비스 도메인과 필요한 개발용 서비스 URL
- 네이버 지도 앱 길찾기 목적지 정보

### 11.1 네이버 Maps API 키 발급

1. 네이버 클라우드 플랫폼 콘솔에 로그인한다.
2. `Services > Application Services > Maps > Application`으로 이동한다.
3. API 이용 약관에 동의하고 새 Application을 등록한다.
4. API 선택에서 `Web Dynamic Map`을 활성화한다.
5. 실제 운영 도메인과 필요한 개발용 URL을 `Web 서비스 URL`에 등록한다. 등록 URL과 실제 서비스 출처가 다르면 인증에 실패할 수 있다.
6. 발급된 Client ID를 확인해 지도 스크립트의 `ncpKeyId`에 주입한다. Client Secret은 브라우저 HTML에 포함하지 않는다.
7. 키 발급 후 정확한 장소 좌표, 줌 레벨과 단일 마커를 연결하고, 실패 시 현재 placeholder 영역에 주소·길찾기 안내를 표시한다.

공식 참고 문서:

- [Maps Application 등록](https://guide.ncloud-docs.com/docs/maps-app/)
- [NAVER Maps JavaScript API v3 Client ID 발급](https://navermaps.github.io/maps.js.en/docs/tutorial-1-Getting-Client-ID.html)
- [Web Dynamic Map 시작하기](https://navermaps.github.io/maps.js.en/docs/tutorial-2-Getting-Started.html)
